## 二、A 类：采集了但界面看不到（最该先修）

### A1. 磁盘 SMART 健康数据（严重）

**现状**：`core/diskhealth.py` 能读出介质类型（SSD/HDD）、SMART 健康、4K 对齐、
TRIM 状态，但**只在 `health.probe_system()` 内部调用一次**，结果只用来算分。
磁盘页只显示容量、读写速率、分区列表。

**影响**：用户看不到「我的硬盘是不是快坏了」。这是系统工具里最有价值的信息之一，
采集了却藏起来，等于白写 214 行代码。

**修法**：磁盘页加一张「磁盘健康」卡片，显示：

```
介质类型    SSD
健康状态    正常
4K 对齐     已对齐
TRIM        已启用
```

**工作量**：小（半天）。数据已经有了，纯 UI。

### A2. `sysinfo.mac` 死字段

**现状**：`SysInfo` 里定义了 `mac` 字段，但 `_network_info()` 从来没赋值，
系统信息页也没有这一行。

**修法**：要么补上 MAC 采集 + 显示，要么删掉字段。倾向补上（`uuid.getnode()` 一行）。

**工作量**：极小。

## 三、B 类：接了但方式不对

### B1. 软件页同步加载（会卡顿）

**现状**：

```python
def refresh(self):
    self._apps = appmgr.list_installed()   # ← 在 UI 线程跑
```

`list_installed()` 要枚举 HKLM/HKCU 两个 Uninstall 根键下的所有子键，逐个读
DisplayName/UninstallString 等 6-8 个值。机器上装 100 个软件就是 600+ 次注册表调用，
**主线程会明显卡一下**。

**影响**：点「刷新」时界面顿住，用户以为程序没反应。

**修法**：接任务中心，和其它扫描页一致：

```python
self.tasks.submit("software", "读取已安装软件", self._make_task())
```

`store` 里已经有 `SoftwareState` 和 `software_changed` 信号，**只是没人用**。

**工作量**：小（半天）。模式已经成熟，照着 bigfile 页抄即可。

### B2. 任务进度不全局可见（信息断层）

**现状**：`MainWindow` **一处都没有订阅** `tasks.started / progress / finished /
queue_changed`。每个页面自己订阅自己的 task_id。

**后果**：在重复文件页点「开始扫描」，然后切到概览页 —— **界面上完全看不出
有任务在跑**。查重可能要 5 分钟，用户会以为没生效，回去再点一次（被
`is_busy` 挡住，什么也不发生）。

**修法**：主窗口订阅 `tasks.started / progress / queue_changed`，在顶部状态条
（`lbl_reclaim` 旁边）显示：

```
正在查找重复文件 42%
```

队列里还有任务时显示「+2 排队」。

**工作量**：小（半天）。

### B3. 体检里三处 fallback 文案过时

**现状**：

```python
_size(snapshot.social_bytes) if snapshot.has_social else "待接入"
```

社交缓存、注册表、更新残留三项**都已经接好了**，但未扫描时仍显示「待接入」，
读起来像是功能没做。应改为「未扫描」。

**工作量**：极小（改 3 个字符串）。

## 四、C 类：完全没接

### C1. 任务浮层 / 任务中心 UI

方案里的「右下角浮层，可展开看进度/取消」。当前每个页面各自显示进度，
没有全局入口。做完 B2 之后这个需求会弱化，但「多个任务排队时能看到队列」
仍然有价值。

**建议**：B2 做完再看，可能不需要独立浮层。

### C2. 撤销入口

**现状**：清理、查重删除都进回收站，但**没有任何「撤销上一次操作」的入口**。
用户想反悔只能自己去回收站页翻。

**修法**：主窗口记一条「最近操作」（时间、动作、影响文件数、体积），
在顶部状态条旁边显示「已清理 1,234 个文件 · 撤销」，点了打开回收站页。

**工作量**：中。需要 `act` 层记录操作。

### C3. 计划任务独立页

启动项页已经能列出计划任务（`startup.list_entries` 里 `source == "task"`），
但混在一起看不出触发器、上次运行结果、下次运行时间。

**工作量**：小。数据基本都有，加个筛选视图即可。

### C4. 右键菜单管理

扫 `HKCU\Software\Classes\*\shell` 等位置的菜单项，可禁用。

**工作量**：中。可以复用注册表模块的「备份后删除」机制。

### C5. 卸载残留清理

扫 `%LOCALAPPDATA%` / `%APPDATA%` / `%PROGRAMDATA%` 里没被任何已安装软件认领的目录。

**风险**：**误判即用户数据丢失**。启发式天然不可靠 —— 很多软件用与产品名
完全无关的目录名（比如 VS Code 用 `Code`、微信 4.0 用 `xwechat_files`）。

**建议**：**暂不做**。真要做必须是四重保护：只列出不自动勾选、风险分级、
删除进回收站、每条二次确认。

> **2026-11-14 补充：已按上述四重保护实现**，见 `core/leftover.py` +
> 「软件管理 → 卸载残留」分段。实现过程中发现原方案低估了一个坑：
> 装在盘根、不写注册表、没有卸载器的绿色软件（如 `E:\ApkStart`），
> `list_installed` 完全看不见，它的 `%APPDATA%` 目录会被当成 13 GB 的残留。
> 补了两条认领证据才压住：正在运行的进程名、以及磁盘根/程序目录里的同名文件夹。
> 判定规则写成四道闸门，文件头有详细说明。

### C6. 长尾功能

目录迁移（junction）、安装包专清、驱动更新提示、自定义清理规则。
按需再说。

## 六、不建议做的

| 项 | 理由 |
|---|---|
| 卸载残留清理 | 启发式误判 = 用户数据丢失，收益与风险不成正比 |
| 系统精简 / 组件移除 | 一次误删可能让系统更新失败 |
| 驱动自动安装 | 变砖风险，只做「提示可更新」 |
| 多语言 | 用户是中文环境，投入产出比低 |
| 独立任务浮层 | 批次一做完「任务进度全局可见」后，需求基本被覆盖 |

---

## 七、一句话总结

**当前最大的问题不是功能少，是「有数据没露出」。**

磁盘 SMART 采集了 214 行代码却没有任何界面，软件列表有状态对象却没人订阅，
任务在后台跑但切页就看不见。这三件事修完，比再加三个新功能的价值都大。
