# 打包说明：Windows 安装包 / macOS 安装包

## 一、现状先说清楚

| 平台 | 之前有什么 | 现在有什么 | 能不能用 |
|---|---|---|---|
| Windows | `tools/build.py` → 单文件便携版 exe（无安装包） | 便携版 exe **+ 安装包 setup.exe** | ✅ 两个都能用 |
| macOS | 无 | `tools/build_macos.py` → `.app` + `.dmg` | ⚠️ 能装、能启动，但运行时会提示「仅支持 Windows」 |

原因不在打包，在**代码本身是 Windows 专用的**：注册表（`winreg`）、内存统计
（`GlobalMemoryStatusEx`）、磁盘健康（`DeviceIoControl`）、启动项（`schtasks` +
Run 键）、回收站（`SHQueryRecycleBin`）、单实例（命名互斥体）、进程枚举里的
Windows 分支……一共 40 多个模块依赖这些接口。在 macOS 上连 `import core.winmem`
都会失败。

所以这次做的是**打包能力**，不是移植：macOS 产物是一个「能安装、能启动、
会明确告知不支持」的壳子（`main.py` 的 `_require_windows()` 负责这句话）。
真要支持 macOS，移植清单在第五节。

## 二、依赖

```bash
python -m pip install -r requirements-build.txt   # PySide6 + psutil + PyInstaller
```

- Python 3.10+（实测 3.13.14）
- **不需要** Inno Setup / NSIS；Windows 安装器本身就是一个 PyInstaller 打的
  Qt 小程序（`installer/installer_app.py`），装环境不用管理员权限
- macOS 需要 Xcode 命令行工具（`xcode-select --install`），`hdiutil`、`codesign`
  都是系统自带的

## 三、Windows：便携版 + 安装包

### 3.1 便携版（原有流程，未改动）

```bash
python tools/build.py            # 版本号不变
python tools/build.py --bump     # PATCH +1 再打包（发新版用）
```

产物与归档：

```
dist/Windows系统管家.exe                     单文件，双击即用
releases/vX.Y.Z/Windows系统管家-vX.Y.Z.exe   带版本号的副本
releases/vX.Y.Z/Windows系统管家-vX.Y.Z.zip   带 README + CRC 的分发包
releases/vX.Y.Z/SHA256SUMS.txt
```

### 3.2 安装包（新增）

```bash
python tools/build_installer.py           # 用 dist/ 里现成的 exe
python tools/build_installer.py --build   # 先打便携版，再打安装包
```

产物：

```
dist/Windows系统管家-vX.Y.Z-setup.exe        实测 64.2 MB
releases/vX.Y.Z/Windows系统管家-vX.Y.Z-setup.exe
```

体积构成（v0.0.51 实测）：载荷 36.9 MB（程序 29.9 + 卸载器 7.0）+ 安装界面自带的一套 Qt 约 25 MB。
**这是「不需要任何外部工具链」的代价**。介意体积的话，用 Inno Setup 的 LZMA2 重打一份约 32 MB，
但那样就多一个工具依赖、装工具还要管理员权限 —— 两条路都留着，自己选。

它做的事（全部按当前用户，不弹 UAC）：

| 步骤 | 说明 |
|---|---|
| 复制文件 | 安装到 `%LOCALAPPDATA%\Programs\Windows系统管家\`，可改 |
| 快捷方式 | 开始菜单（程序 + 卸载）、桌面（可选） |
| 卸载登记 | `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\Windows系统管家`，出现在「设置 → 应用」里 |
| 卸载器 | 同目录的 `uninstall.exe`，可单独运行，会问要不要连用户数据一起删；删自己时落一个批处理到 `%TEMP%` 等进程退出后重试（见 3.4） |

命令行参数：

```bat
Windows系统管家-v0.0.51-setup.exe                 图形安装
Windows系统管家-v0.0.51-setup.exe /S              静默装到默认目录
Windows系统管家-v0.0.51-setup.exe /S /D=D:\Tools\wm   静默装到指定目录
"%LOCALAPPDATA%\Programs\Windows系统管家\uninstall.exe" /S /data   静默卸载并删数据
```

安装器内部结构（出问题时按这个查）：

```
setup.exe
└─ payload/
   ├─ Windows系统管家.exe   真正的程序（带 requireAdministrator 清单）
   ├─ uninstall.exe         卸载器（不含 Qt，约 7 MB）
   ├─ icon.png              只给安装界面用，不会复制进安装目录
   ├─ manifest.json         名称 / 版本 / 主程序文件名
   └─ README.txt            装完留在安装目录里的说明（装完目录里就这三样：
                            程序、卸载器、README）
```

### 3.3 签名（重要，但不是必须）

未签名的 exe 在别人机器上会：

- 首次运行弹 SmartScreen「Windows 已保护你的电脑」
- 被杀软误报的概率明显升高（PyInstaller 单文件的老问题）

有证书后给两个 exe 各签一次即可，`tools/build_installer.py` 里预留了位置：

```bat
signtool sign /fd SHA256 /tr http://timestamp.digicert.com /td SHA256 ^
  /a dist\Windows系统管家.exe
signtool sign /fd SHA256 /tr http://timestamp.digicert.com /td SHA256 ^
  /a dist\Windows系统管家-v0.0.51-setup.exe
```

顺序很重要：**先签程序，再打安装包，最后签安装包**（安装包里裹着程序）。

### 3.4 卸载器为什么用批处理

`uninstall.exe` 自己就在要被删的目录里，Windows 不允许删掉正在运行的文件，
只能交给外部进程晚一步干。这里踩过一个坑：一开始用一条
`cmd /c "for /l %i in (1,1,15) do (rmdir ...)"` 想一步搞定，结果
**rmdir 一次都没执行** —— `for /l` 的循环变量在命令行里写 `%i`、在批处理
文件里写 `%%i`，混用会静默失败。现象是卸载后目录里只剩一个 `uninstall.exe`。

现在把逻辑写进 `%TEMP%\wm-uninstall.bat`，用批处理语法，出问题还能直接打开
文件看。批处理做三件事：等两秒 → 最多重试 20 次删目录（每次隔一秒，避开
杀软扫描 / 缩略图占用）→ 删掉自己。实测卸载后 **约 3 秒**目录消失。

**别再让窗口弹出来**：这个批处理由 `CREATE_NO_WINDOW` 启动（分配一个不显示的
控制台，子进程继承它），标准输入输出全接空设备。早先同时给了
`DETACHED_PROCESS`，两者意图互斥，子进程会自己新建一个控制台 —— 用户看到的
就是黑窗口一闪。批处理里的等待用 `ping -n` 而不是 `timeout`：后者需要可用的
控制台输入，输入被重定向时会直接报错退出。

回归验证：`python tools/check_uninstall_silent.py`（真装卸 + 轮询屏幕上的
控制台窗口，要求全程零新窗口）。

## 四、macOS：.app + .dmg

只能在 macOS 上跑（`hdiutil`、`.app` 结构、代码签名都无法在 Windows 交叉产出）：

```bash
python tools/build_macos.py            # 出 .app 和 .dmg
python tools/build_macos.py --no-dmg   # 只出 .app，调试快
CODESIGN_IDENTITY="Developer ID Application: 你的名字 (TEAMID)" \
  python tools/build_macos.py          # 顺带签名
```

产物：

```
dist/Windows系统管家.app
dist/Windows系统管家-vX.Y.Z.dmg     约 55 MB
```

细节：

- 用 `--onedir` 而不是 `--onefile`：macOS 上单文件每次启动都要解包到临时目录，
  慢且更容易被 Gatekeeper 拦
- 图标 `assets/icon.icns`：由 `tools/make_icns.py` 从 `assets/icon.png` 生成
  （纯 Python 写 ICNS 容器，Windows 上也能生成，不依赖 `iconutil`）
- `.dmg` 里放了 `Applications` 替身，用户拖进去就算装好
- 未签名 + 未公证的 dmg，别人打开会被 Gatekeeper 拦住，需要在
  「系统设置 → 隐私与安全性」里手动允许，或做公证：

```bash
xcrun notarytool submit dist/Windows系统管家-vX.Y.Z.dmg \
  --apple-id "$APPLE_ID" --team-id "$TEAM_ID" --password "$APP_PASSWORD" --wait
xcrun stapler staple dist/Windows系统管家-vX.Y.Z.dmg
```

> 目前 `main.py` 在非 Windows 平台会弹一句「只支持 Windows」然后退出 ——
> 这是有意的：宁可给一句人话，也不要让用户看 `ImportError: No module named 'winreg'`。

## 五、如果真要支持 macOS：移植清单

按依赖从重到轻排，前四项不做完，程序跑不起来：

| 模块 | 现在依赖的 Windows 接口 | macOS 对应做法 |
|---|---|---|
| `core/winmem.py` | `GlobalMemoryStatusEx`、性能计数器 | `vm_stat` / `sysctl` / `host_statistics64` |
| `core/winpath.py` | 系统盘符、已知文件夹 | `~/Library/...`、`/Volumes` |
| `core/registry.py` | `winreg` | 无对应物，功能整体移除（改用 `launchd` plist） |
| `core/startup.py` | `schtasks`、Run 键 | `LaunchAgents` plist |
| `core/single_instance.py` | 命名互斥体 | `fcntl.flock` 或 `QSharedMemory` |
| `core/diskhealth.py` | `DeviceIoControl` + SMART | `diskutil` / `smartctl` |
| `core/recycle.py` | `SHQueryRecycleBin` | `~/.Trash` 体积统计 |
| `core/activation.py` | `slmgr` / 注册表 | 无对应物 |
| `core/sysinfo.py` | WMI / `Win32_*` | `system_profiler -json` |
| `core/cleaner.py` 等 | 各页规则表写死 `%LOCALAPPDATA%` 等 | 按平台取目录 |
| `ui/theme_dark.py` | `DwmGetColorizationColor` 取系统强调色 | `defaults read -g AppleAccentColor` |
| `ui/winround.py` | DWM 圆角 / `SetWindowRgn` | 直接不调用（macOS 自带圆角） |

工作量评估：**不是加个 platform 分支能解决的**，等于把「系统层」重写一遍，
UI 层（`ui/` 与 `core/store.py`）可以原样复用。建议真要做时先只移一个页面
（性能监控）验证链路，再逐页推进。

> 具体怎么切平台层、每个模块对应 macOS 的哪个接口、建议的推进顺序，见
> [`macOS适配指南.md`](macOS适配指南.md)。那份是动手文档，这份只讲打包。

## 六、CI

`.github/workflows/build.yml`：推 `v*` 标签或手动触发，两个 job 并行出包，
产物在 Actions → Artifacts 里下载。

- `windows-2022`：便携版 + 安装包
- `macos-14`：`.app` + `.dmg`（可用 Secrets 里的 `CODESIGN_IDENTITY` 自动签名）

CI 只负责**构建**，不负责发布。发布仍走 `tools/sync_oss.py` /
`tools/push_github.py`，密钥不进 CI。

## 七、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| `build.py` 说「旧版本仍在运行，输出到 dist_pending」 | 程序开着，exe 被锁。关掉窗口重跑，或手动把 `dist_pending` 里的文件覆盖过去 |
| 安装时提示「程序正在运行，请先退出」 | 安装器会先探测安装目录里的 exe 是否可改名（被锁就是正在跑） |
| 装完双击没反应 / 弹 UAC | 正常：程序清单要求管理员权限（要清理系统目录）；拒绝 UAC 就只能看不能清 |
| 杀软报毒 | PyInstaller 单文件的常见误报。加白名单，或换 onedir + 签名；本项目 Windows 侧仍是 onefile |
| `.dmg` 打不开，提示「已损坏」 | 未签名/未公证。右键 → 打开，或 `xattr -dr com.apple.quarantine /Applications/xxx.app` |
| `build_installer.py` 报 `ModuleNotFoundError: PyInstaller` | 装 `requirements-build.txt`，不是 `requirements.txt` |
